# Browser latency probe

The real viewer, local Next server, Bops Cloud and input/capture pipeline are exercised through the two-person stack. A loopback proxy delays data independently in each direction. Each new upstream TCP connection also pays one modeled round trip. Each incoming app connection has its own upstream keep-alive agent, preserving connection lifetime and avoiding reuse across unrelated app sockets. Connection open/ready/close and each act's reused/new connection status are timestamped. HTTP streams and WebSocket upgrades both work. The local stack has no TLS: real HTTPS adds one more round trip per new connection than measured here. The orchestrator's supplied remote connect timings are context, not measurements made by this probe.

Only the hidden viewer queue and Cloud/runner boundaries need opt-in instrumentation (`BOPS_BROWSER_PROBE=1`), silent by default. It logs mouse geometry and frame metadata, never typed text or credentials. The viewer probe observes EventSource, reuses the app's bitmap decode and samples actual canvas pixels in requestAnimationFrame. Colour matching uses expected RGB within 35 levels. No second screencast or decoder runs on the measured viewer.

Acceptance and proof:

- `scripts/verify browser-speed`: regression checks, Node syntax, `npx tsc --noEmit` and touched-file ESLint. Tests include the saved real CPU counterexample, click release attribution, missing-hop rejection, cleanup failures, real streaming and cold/warm connection tests.
- `node scripts/probe-browser-speed.mjs --link-ms 0 --out .scratch/probe-0` (repeat with 35): opens the owner's Browser tab and takes control through the UI; 30 rest clicks at least 600 ms apart, 15 clicks after two seconds moving, 30 hovers, 10 clicks after six seconds idle, and five seconds scrolling. Idle clicks use down/up at the existing pointer position, without an extra mouse move warming the connection. Raw JSON and n/median/p90 summaries include all hops and per-scenario counts of acts opening connections.
- Several people at once: add `--driver sam --watchers 2` (sam drives as a Member of the owner's shared workspace while two of the owner's windows watch; `--driver owner --watchers 1` the other way round). Each watcher is its own stream; the summary adds `watcher_<scenario>_to_photon_ms` (from the driver's input to the watcher's first paint of it), `watcher_<scenario>_behind_driver_ms` and `watcher_scroll_fps`. Watchers run on the same Mac, so they share its CPU with the driver.
- `node scripts/probe-computer-side.mjs --out .scratch/computer-probe`: Node 22+ and Chrome, no Playwright required; an owned headless Chrome/profile only, relay screencast settings, 30 CDP clicks and five seconds scrolling. Actual dispatch-to-JPEG and page-handler-to-JPEG timings lead its summary.
- Commit before measuring and change no tracked code during a run. Run 0 ms, 35 ms, then the standalone reference serially.
- Stop the stack and compare the listener list with the pre-run inventory. Cleanup saves raw observations before teardown and attempts every resource close even when evidence copying or stop fails.

CPU is reported, never a gate. Sampling uses each process's own cumulative `ps time`, excluding reaped-child aggregation. Each interval sums nonnegative deltas only for PIDs present in both snapshots and records appearing/exiting PID counts. This slightly undercounts helpers' work at process boundaries. Sampling failures are saved as CPU warnings and cannot discard latency results. Counters have 10 ms precision on this Mac. Relay CPU is the stack parent process, including fixture servers and the delay proxy, excluding its children. Scenario summaries include queue drain; FPS and bandwidth use exactly five one-second scroll buckets.

All ordinary observations use epoch milliseconds from Node/browser performance clocks on this Mac. Click causal hops follow the release that fires `click`; queue depth comes from the physical press. Input-to-release-send includes queued moves, the press round trip and any new connection setup on that press. Proxy data-ready/socket-write timestamps separate outgoing propagation from connection setup/agent wait. Per-input joins are bounded by input and first paint, and identify the same changed source frame. Missing latency observations fail; missing CPU does not.

Chrome metadata caveat: [Chromium's implementation](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/browser/devtools/protocol/page_handler.cc) uses expected display time for `metadata.timestamp` (`ScreencastFrameTimestamp`), which may follow JPEG delivery. Keep signed metadata deltas, and use actual encoded-frame callback timing for draw/encode and transport durations. Socket creation/reuse follows the [Node HTTP Agent API](https://nodejs.org/api/http.html#agentcreateconnectionoptions-callback).

Scope: local fixtures, `next dev`, no physical display measurement, production, real Orgo computer, paid model calls, transport fix, new npm dependencies, installed Bops changes, push, PR or deploy. Two required link conditions only; the optional runner-delay condition is deferred to stay within the one authorized campaign. The probe stops a stack it starts and refuses a mismatched reused stack. Revert the probe commits to remove the tooling; timing logs remain off unless explicitly enabled.
